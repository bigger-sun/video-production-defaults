# video-production-defaults

视频生产的**路由与质量管控层**。给 Codex / Claude Code / WorkBuddy 用的 skill：在动手写脚本或分镜之前，先把「做哪种视频、按什么标准做、怎么验收」定下来。

本技能只做**选型与门控**，具体渲染交给专用执行器（Remotion、Python 模板脚本等），不在这里重复实现渲染细节。

## 解决什么问题

AI 做视频最大的坑通常不是画面，而是判断：

- 选错格式 —— 该讲清楚的用了 8 秒短视频，该快的做成了 3 分钟教程
- 前 3 秒没有钩子，完播率崩
- 文字压进安全区外，被平台 UI 挡住
- 交付前不验收，错版直接发出去

本技能把这些判断固化成可执行的流程，而不是靠临场感觉。

## 两类默认格式

先选定**唯一**主格式，再开始写脚本。

| 格式 | 适用 | 默认输出 |
| --- | --- | --- |
| **Narrated demo** 解说演示 | 教程、产品介绍、新功能讲解、需要解释或真实界面演示的工作流 | 16:9，通常 30–120 秒，克隆音色旁白 + 数字人 + 截图或录屏 |
| **Golden Short** 黄金短视频 | 榜单、排行、步骤、要点提示、警示、快技巧 | 通常 8–10 秒，文字主导，默认 9:16（视频号） |

判断标准：**理解依赖解释或真实操作 → 用解说；一眼能看懂的 → 用短视频。** 用户明确指定时以用户为准。

## 三道门控

1. **指标门控** —— 每个选题先过 `references/video-account-ai.md` 的五个问题（观众为什么停下来 / 看完 / 点赞评论 / 转发 / 关注），答不出三个就先改选题，不进入制作。
2. **布局门控** —— 按 `references/layout-rules.md` 的固定优先级执行：**中心优先 → 安全区 → 模块化字号**。宁可恢复居中，也不要缩字号；9:16 的首个可见元素距顶边不少于 200px。
3. **交付门控** —— 交付前校验视频、音频、文字排版与代表性静帧。

## 使用

把本目录放进 skills 目录，Codex / Claude Code / WorkBuddy 会自动加载 `SKILL.md`：

```bash
cp -r video-production-defaults ~/.workbuddy/skills/
```

## 共享默认值

- 不主动生成封面图，除非用户明确要求
- 默认 BGM：`goodfeel.m4a`
- 旁白默认走本地 VoiceStudio 通道（`http://127.0.0.1:3900/mcp`），音频不出网
- 遵守最小必要时长：保住理解与情绪完整的前提下，一秒都不多留

## 注意

- 文档中的 `/Users/biggersun/...` 是本机默认路径（BGM、模板与技能目录），换机器使用时按实际环境调整。
- 本技能的边界**止于验证通过的 MP4 交付**。发布、评论监控与回复、账号运营、发布后数据复盘属于运营环节，不属于视频生产。
